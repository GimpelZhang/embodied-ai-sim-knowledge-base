## 1. 复现目标与背景

### 1.1 目标与预期成果

复现分四个递进目标，前一个是后一个的地基：

| 阶段 | 目标 | 预期成果 | 实际达成 |
|---|---|---|---|
| Stage 1 | 装通环境，跑通现成 VLA 闭环 | 官方任务上拿到可信成功率 + 观测数据落盘 | ✅ 90%（9/10），10 个 ROS bag 共 2.1 GB |
| Stage 2 | LLM 驱动生成新场景并评测 | 生成流水线稳定 + 新场景可评测 | ⚠️ 流水线 6/6，策略得分 0/6（判定为 OOD，非缺陷） |
| Stage 3 P1+P2 | 手机视频 → 3DGS/PGSR 重建 | 达标质量的重建模型 | ⚠️ 4 模型训完，PSNR 22.6–24.5 dB，**未达自设 >25 dB 线** |
| Stage 3 P3+P4 | 重建物转 USD + 注入物理 + 自定义任务闭环 | 自建 real2sim 场景端到端跑通 | ✅ 基础设施 6/6 通过；任务得分 0（预期内 OOD） |
| 深化实现 | 按官方资产规范重做 mesh + 纹理 | 资产结构对齐官方 | ✅ 验证门 G1–G4 通过，G5 两次均 DEFERRED |

**贯穿目标**：验证"用户自己拍一段 MP4 → 变成可跑 VLA 策略的仿真场景"这条 real2sim 链路是否走得通。结论是**链路通、资产质量与策略泛化是两个独立的未完成项**。

### 1.2 环境条件

| 项 | 值 | 备注 |
|---|---|---|
| 形态 | 云服务器，**无显示器、无 X11** | 全程 headless，是多个坑的共同前提 |
| OS / 中间件 | Ubuntu 24.04 Noble ／ ROS 2 Jazzy | 与上游要求一致 |
| GPU（前期） | Tesla V100 32 GB（Volta, **SM 7.0**） | ⛔ **不满足 Isaac Sim 5.1 硬件门槛**，见 P07 |
| GPU（后期） | A100-SXM4-40GB（Ampere, **SM 8.0**） | 深化实现阶段材料记为 A800 40 GB，同属 SM 8.0 |
| 驱动 | `535.288.01` → 升级至 `580.126.09` | 旧版本被 Vulkan 误读为 `535.32`，见 P03 |
| CUDA | 11.8（宿主） | `CUDA_HOME` 未设会拼出畸形 nvcc 路径 |
| 仿真底座 | Isaac Sim 5.1.0（NGC 镜像 22.9 GB） | 本地构建，见 D2 |
| 容器 | docker-ce + compose-plugin + nvidia-container-toolkit | 宿主机**零 Docker 基础**，从头装 |
| 镜像体积 | 主镜像 38.2 GB ／ openpi_server 19.1 GB ／ Isaac 基础 22.9 GB | 全部本地 build |
| 容器运行 UID | **1234**（≠ 宿主用户 UID） | 权限类问题的总根源，见 P05 |
| 策略 | π0 / OpenPI，Policy Server 监听 `:9001` | WebSocket 回传关节目标 |
| 重建环境 | 两个隔离 conda env：`scene_recon`(Py3.10/torch2.7.1)、`pgsr`(Py3.8/torch2.4.1) | 互斥依赖，见 P09 |
| 网络 | 需代理，且**须在三层分别配置** | 见 P02 |

**输入素材**：1 段室内背景视频 + 3 段物体视频（cup / bag / can），抽帧 278–351 帧。尺度校准基准取自随附说明的桌面高度 0.71 m 与 A4 纸 0.297×0.21 m。

## 3. 关键决策与原因

编号 `D1`–`D10` 稳定。"依据"列区分决策来源：**源码**（读上游代码得出）／**实测**（本机跑出的证据）／**外部**（官方 Issue、论文、榜单、README）／**判断**（工程经验推断，风险最高）。

| # | 决策 | 原因 | 依据 | 事后评价 |
|---|---|---|---|---|
| **D1** | 选定 π0 / OpenPI + 现成任务 `s2r_pack_in_supermarket` 作为基线 | 平台原生深度支持 Pi 系列；仓库自带拉取脚本、镜像内预置 Policy Server、任务现成 —— 三者齐备可最快拿到"已知正确"的参照 | 外部 | ✅ 关键正确。有了 90% 基线，后续任何失败都能二分归因 |
| **D2** | 私有 registry 不可达 → 本地构建全部镜像，**但仍打成原 registry 的 tag** | 保留原 tag 可避免修改 compose 引用，减少后续偏离官方配置的面积 | 判断 | ✅ 低成本高收益的兼容技巧 |
| **D3** | 驱动用 `apt install` 升级，**禁止用 `.run` 手装** | `.run` 会造成用户态 GL 库与内核模块版本不一致，产生比原问题更难查的渲染故障 | 判断 | ✅ 正确，属通用铁律 |
| **D4** | 重建流程全部移到**宿主机 conda**，放弃容器内 hloc | 容器构建需代理且耗 30–60 min；重建是离线预处理，不必进容器 | 判断 | ✅ 显著提速。代价是宿主机多了一套依赖 |
| **D5** | gsplat 与 PGSR 分装两个**完全隔离**的 conda env | 两者对 `pycolmap` 需求正面互斥（legacy 版 vs 官方 3.11.1），且连带锁定 `numpy<2` 等 | 实测 | ✅ 唯一可行解，**不要尝试合并** |
| **D6** | 架构定为"3DGS 做视觉层 + 不可见碰撞代理做物理层 + 任务物体单独 overlay" | 纯视觉 3DGS 只是"一团发光的全息投影"，带重力的物体会直接穿透桌面 | 判断 | ✅ 本次复现最重要的架构洞察，且是计划里**没有**的主动发现 |
| **D7** | 放弃"PGSR 点云 → Poisson → mesh"，改按已知真实尺寸建 box/cylinder 代理 | 点云法线噪声大 → mesh 几何不精确 → 做碰撞体会穿模或抓不住；还要额外调 Poisson 参数 | 判断 | ⚠️ 对 pick-and-place 足够，但**副作用被低估**：绕过了人工尺度校准，把尺度问题推迟到下一阶段，直接导致六轮视觉返工 |
| **D8** | 把"改指官方实验室背景"这个已生效的快修**主动回退** | 快修证明了根因（缺灯光），但用官方背景就等于放弃"用实拍 3DGS 当仿真环境"这一 Stage 3 目标 | 判断 | ✅ 少见的、正确的自我纠正：区分"修好了"与"达成目标了" |
| **D9** | 内联点云规模定为 **100K**（而非全量 600K） | 实测 600K 使物理回调掉到 0.25 Hz；100K 可维持 ~4 Hz，而均值像素差仅 1.13 —— 视觉几乎无损 | 实测 | ✅ 教科书式的量化取舍，附随机种子保证可复现 |
| **D10** | 用 `primvars:displayColor` 顶替 UV 贴图流程 | 自写烘焙器要跑 1.5–2.2 h，而 TSDF 融合本就已积分逐顶点 RGB，Hydra 原生支持顶点色 | 判断 | ❌ **已被自我否定**。结构上不对齐官方资产、整体跳过了 `textures/diffuse.jpg`、丢掉 UV 的 texel 密度优势；复盘中自列为"最大耻辱" |

**决策模式观察**：标注为"判断"的决策共 7 条，其中 5 条正确、1 条有被低估的副作用（D7）、1 条被自我否定（D10）。**两条出问题的决策有共同特征：都是为了绕开一段耗时工作而降低目标，且当时都给出了听起来合理的技术理由。**

## 4. 遇到的问题与解决方案

核心章节。编号 `P01`–`P18` 稳定；`★` 表示"下次一定会再遇到"的高频/高价值项。**"无效尝试"列刻意保留** —— 排除路径的价值不低于正解。

### 4.1 容器、网络与权限（P01–P06）

| # | 现象 | 排查过程 | 无效尝试 | 最终解决 |
|---|---|---|---|---|
| **P01** | 官方初始化脚本执行后无任何输出、永久挂起 | 脚本非交互 shell 下无回显；读脚本发现内含交互式 `read -p` | — | 放弃脚本，手动执行等价的 `git clone -b <branch>`；大仓库加 `-c http.postBuffer=524288000` 防传输中断 |
| **P02** ★ | 分别表现为：拉不到 NGC 镜像／装不上 `ros-jazzy-desktop`／`uv sync` 内 `git fetch` 报 `GnuTLS recv error (-9)` | 三个症状看似无关，实为代理在不同层缺失 | 只配 systemd 或只配 `config.json` —— 均只修好三症状之一 | **代理须在三层各配一次**：systemd drop-in（daemon 拉镜像）＋ `config.json`（客户端注入容器）＋ build 时显式 `http_proxy=` 环境变量（构建期子进程）。构建还需 `--network=host` 与 `--build-arg` 代理同时给，Dockerfile 内代理须从 `ARG` 提为 `ENV`，`UV_HTTP_TIMEOUT` 600→1800 |
| **P03** ★ | Isaac Sim 报 `ERROR_INCOMPATIBLE_DRIVER`；相机返回 `shape=(0,)` | 两个独立根因叠加：① NVIDIA container runtime **只注入计算库、不注入 GL/Vulkan 渲染库**；② 驱动 `535.288.01` 经 Vulkan 编码后被读成 `535.32`，触发 `>=535.129` 检查误判为过旧 | 用 `.run` 手装驱动（会导致 GL 库与内核模块不一致，见 D3） | ① 从宿主机 cp `libGLX_nvidia` / `libEGL_nvidia` / `libnvidia-glcore` 与 `nvidia_icd.json` 挂进容器；② `apt install nvidia-driver-580` |
| **P04** | 容器启动即退出；容器内解析不到 assets 目录 | 读 `entrypoint.sh` 见开头 `set -e`，其 `setfacl` 目标目录不存在即非零退出 → 整个容器挂；软链接是在宿主机建的，存的是**宿主机绝对路径** | 在宿主机重建软链接（方向错，仍无效） | 预创建 `setfacl` 目标目录；**软链接必须在容器内、用容器内路径创建** |
| **P05** ★ | `PermissionError`（`shutil.copy` 内部 `os.chmod`）／host 侧写文件 EACCES／`mv` 隐藏旧场景被拒 —— **同一根因踩 3 次** | 容器以 **UID 1234** 运行，与宿主用户 UID 不同；两侧交替写同一批文件必然冲突 | 逐个文件 `chmod`（治不了新生成的文件） | 开工第一步就把相关目录整体 `chown` 到容器 UID。**原则：跨边界文件操作，要么全程在容器内做，要么全程在宿主机做，不要交替** |
| **P06** | 宿主机重启后，之前修好的渲染问题（P03）全部复发 | GL 库被放在 tmpfs 临时目录下，重启即丢 | 只重新 cp 库文件 —— 仍然失败 | 重填库文件后**必须重建容器**（旧容器挂载的是空目录快照）；长期解法是把库永久迁出 tmpfs |

### 5.3 需要人工纠正的频率

## 6. 可复用的经验教训

编号 `L1`–`L8` 稳定。按"下次能省多少时间"降序排列。

### L1 · 装任何 CUDA 扩展前先查 compute capability；OOM 数字不合理时先怀疑架构不匹配，不要怀疑显存

**理由**：同一根因在本次复现里以**三种完全不同的面貌**出现（运行时 kernel crash、100 元素张量报 OOM、请求 56 GiB），共浪费数小时，而修复只需重编译 5 分钟。CUDA 架构不匹配的报错**几乎从不指向真因** —— 驱动返回 `cudaErrorNoBinaryForGpu` 后，上层框架回落 CPU dispatcher 并错算内存需求，于是伪装成显存问题。

**适用场景**：任何需要现场编译 CUDA 扩展的项目（3DGS/gsplat/PGSR、自定义算子、diff-rasterizer）。**动作**：`nvidia-smi --query-gpu=name,compute_cap` 作为第 0 步，并把值显式写进 `TORCH_CUDA_ARCH_LIST`；换 GPU 后**必须重编译所有扩展**，不要假设 `.so` 是为当前卡编译的。判据：显存请求数字荒谬（远超物理显存、或极小张量报 OOM）= 架构问题，不是容量问题。

### L2 · 给每个长任务预设"独立于日志的存活判据"

**理由**：本次复现至少三次遇到"进程 99% CPU、日志持续刷屏、实则已死或永不产出"。最贵的一次耗掉 1h43min，原因是主线程还在打印物理回调日志，而干活的 worker 线程早已被超时静默杀死。**日志有输出 ≠ 任务在推进。**

**适用场景**：所有仿真/训练/渲染类长任务。**可用判据**：① GPU 利用率仅 1–2% 且显存占用为 0 → 渲染或初始化已失败；② 端口只有 LISTEN 没有 ESTABLISHED → 客户端从未真正连上；③ 服务就绪只认日志里的明确标记（如 `server listening on ...`），不认 `docker ps` 的 `Up` 状态；④ 预设"某标记超过 N 分钟未出现就 kill"的硬性上限；⑤ 某步耗时超过预期 2 倍即视为异常。

### L3 · 开工第一步是读源码核对计划，而不是执行计划

**理由**：本次七个计划变更点中有三个源于"计划里的东西在 release 中不存在"（脚本、目录、WebUI、向量检索组件、专用入口）。快速迭代的开源仿真项目里，**文档滞后于代码是常态而非例外**。

**适用场景**：任何依据博客/论文附录/较早版本文档开始的复现。**动作**：把"计划假设 vs 实际代码"的差异整理成一张表（本次称为"N 个关键差异速读"）放在文档最前面，并明确告知后来者"不要再去找计划里的那些脚本"。特别注意：**上游脚本常假设有人坐在终端前**（交互式 `read`），非交互环境会直接挂死。

### L4 · 跨容器边界的文件操作，要么全程在容器内做，要么全程在宿主机做

**理由**：容器运行 UID 与宿主用户 UID 不同，两侧交替写同一批文件会反复产生 `PermissionError` —— 本次同一根因踩了 3 次，且逐个 `chmod` 治不了新生成的文件。同源问题还有：**在宿主机创建的软链接存的是宿主机绝对路径，容器内解析不到**。

**适用场景**：所有"宿主机预处理 + 容器内运行"的混合工作流。**动作**：开工第一步就把共享目录整体 `chown` 到容器 UID；软链接必须在容器内用容器内路径创建；另注意放在 tmpfs 下的手工补齐文件**重启即丢，且重填后还须重建容器**（旧容器挂的是空目录快照）。

### L5 · 依赖需求正面互斥时，直接隔离环境，不要尝试调和

**理由**：本次两个重建工具对同一库的版本需求互斥（legacy 版 vs 官方 3.11.1），并连带牵动 numpy 主版本。试图合并只会陷入版本连锁（`UnicodeDecodeError` → 类不存在 → `OverflowError`）。隔离成两个 env 是**唯一可行解**。

**适用场景**：把多个研究代码库串成流水线时（重建 + 训练 + 转换往往各有一套锁定依赖）。**动作**：一个工具一个 env，用文件在磁盘上交接而非在同一进程里交接；PEP 517 构建隔离会看不到已装的 torch，**torch 依赖型扩展一律加 `--no-build-isolation`**；注意 `conda activate` 不把 env 的 bin 传给子进程 PATH，torch 的 `shutil.which` 检查会误报缺少构建工具。

### L6 · 让 LLM 产出结构化代码/DSL，示例的价值远高于描述；且防御必须冗余

**理由**：仅用自然语言描述 API 约束时，模型对函数签名的"记忆"会失准，导致参数顺序调换、多传关键字参数 —— 本次 Round 2 **3 个场景全部因此失败**。补上"合法签名逐条清单 + 一份已成功运行的完整示例"后一次通过。

**适用场景**：所有让模型生成受限语法产物的任务（场景 DSL、配置、IaC、迁移脚本）。**动作**：① 贴完整可运行的 EXEMPLAR 让模型模仿，而非让它凭记忆写；② 合法资产/枚举值要 `ls` 出真实白名单注入 prompt，并在每条 spec 里显式钉死 id（防幻觉）；③ 输出清洗要**双保险** —— prompt 声明禁用 markdown 围栏 **且** 代码侧正则强 strip；④ 失败时把上一次的报错反馈回去重试。

### L7 · 验证要用数值阈值，并且必须校验产物真实落地

**理由**：肉眼判断"看起来对了"在视觉类任务里极不可靠；而只检查结构的验证门会放过假绿灯 —— 本次出现过 G1–G4 全 PASS 而贴图目录实际为空（产物留在中转目录没 copy 出去）。

**适用场景**：所有输出为图像/几何/资产的流水线。**动作**：① 建分级门禁，每级带可判定数值（静态校验 → prim/材质计数 → 无头加载打印成功标记 → 渲染帧 ROI 标准差与聚类差异 → 全闭环像素指标）；② **从产物文件出发解析相对路径，确认被引用文件真实存在且体积合理**，不要只查引用写没写；③ 明确哪些指标不在本次考核范围（如策略得分属模型能力，与资产升级无关），避免用不可控项否定可控成果。

### L8 · 遇到耗时工作时，禁止用"我有更聪明的方法"降低目标；正确的加速是先降数据量，再优化实现

**理由**：本次两次质量事故都源于此 —— 用顶点色顶替 UV 贴图流程（自评"最大耻辱"）、绕过规范流程改用替代算法（同时掩盖了真正的 CUDA 根因）。反面对照：卡在纯 Python 光栅化时试了五种加速库全失败，**正解是先激进抽面把面数降两个量级**，之后连纯 numpy 向量化都只需 5–20 秒。

**适用场景**：任何"计划要求的路径看起来太慢"的时刻。**动作**：把计划文档当作唯一真值源（本次称其为"宪法地位"）；如果确实要偏离，必须显式记录偏离项与代价，而**不能在交付时把替代方案描述成已完成原目标**。同时：自设的合格线未达到时，要么返工，要么写明为何接受 —— 静默放过会在后续阶段以数倍成本回来。
