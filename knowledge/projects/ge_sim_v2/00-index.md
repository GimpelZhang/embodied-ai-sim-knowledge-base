## 一句话定位

**GE-Sim 2.0 是一个"动作条件视频世界模拟器"**：给它一张首帧 + 一条动作轨迹，它生成机器人执行该动作的三视角视频，并**额外解码出本体感觉状态**、**用内置评判器给出成功概率**。它用**神经网络生成**替代了传统仿真器的**物理解算 + 渲染**。

## 三点摘要（选型时先看这个）

1. **它不是物理仿真器，而是"动作条件视频生成器"。** **没有物理引擎、没有渲染器、没有场景文件**，不能增删物体、不能换本体、不能改相机数量与位置（三视角 head / left_wrist / right_wrist 固定）。**只出 RGB** —— 深度 / 激光 / IMU / 力矩 / 触觉 / 分割全部缺失。它擅长回答"**这个策略在这类场景里看起来会怎么动**"，不擅长回答"**这件事在物理上会不会成功**"。

2. **开源是"可用的推理发行版"，不是"可复现的研究发行版"。** 推理侧模型实现（DiT / VAE / 调度器 / pose expert / raymap，约 **8 200 行**，占全仓 72%）与**蒸馏版权重**确实发布了；但**训练与蒸馏代码、数据管线、非蒸馏权重、World Judge 奖励模型、机器人 URDF 全部未发布**。后果很具体：**开箱即用时 `reward` 与 `progress` 恒为 `None`** —— 论文把"自带可验证奖励"作为核心差异化卖点，而这一块要自己补。

3. **三处宣传口径必须打折。** ① **"100 帧 / 2.3 秒"是措辞问题** —— 实际生成 **25 帧**，4× 跳帧后"覆盖"约 100 帧的时间跨度（§8.2 矛盾 1，已查清）；② **"可做 RL"只见于公众号**，官网只说 "Close-loop Learning"，论文把 RL 列为**未来工作**，正文只演示离线过滤式 BC（矛盾 2）；③ **"登顶 WorldArena"指的是活榜而非那篇基准论文**（论文正文 grep `GE-Sim` **命中 0 次**），且**该基准作者自述 EWMScore 与动作规划表现仅弱相关（r=0.36）**（矛盾 5）。

### 经验层 / 排障层的三点摘要

1. **本次复现是"用它评测策略"而不是"复现它的论文数字"** —— 五个阶段：打通世界模型 + π0.5 闭环（**实测仅 0.88 帧/s，约 0.055× 实时**）→ 生成 46 个泛化场景 → 批量评测（OSR 6.5 %）→ 在世界模型内用 **RWR** 自进化（留出集 **30 % → 80 %**）→ 上 RoboColiseum 线上盲测。
2. **最贵的一类问题是"程序不报错但结论是错的"**（排障层 E 类）。典型：一个任务文本常量被三方消费，导致首轮全量评测得 **0 %** 的**假阴性**；对策是「审计四件套」（回退计数 / 动作非退化 / 帧数对账 / 输入侧测量），见 `ai_knowledge.md` §6 `L01`。
3. **流程上最值得复制的一条**：Stage 4 起改为**写码前逐条源码核验计划**，约 2 小时前置拦下 9 条致命错误，执行期 **0 error / 0 abort**；对照 Stage 1 边写边撞的 **10 处**计划-源码不符（`ai_knowledge.md` §2.3、§6 `L02`）。

### 代码层的三点摘要

1. **它是薄编排层，不含模型代码** —— 全部 8.8 k 行（41 个 `.py` / 7830 行 + 14 个 `.sh`）都在"拉服务 / 桥数据 / 判分 / 出报告 / 自检"，上游本体以 submodule 引用且**只改了一行**（关 `sparge_attention`）；训练器、判分器替身、线上 agent 是本仓库**净新增**的三块。
2. **配置无统一系统** —— 只有 Stage 2 有 YAML，Stage 3/4/5 的超参和路径全是模块顶部大写常量，**改参数=改源码**；**`未发现` `requirements.txt` / `setup.py` / `pyproject.toml` / `environment.yml`**，依赖只在仓库 `CLAUDE.md` 的三环境表里，换机必手装。
3. **最大的风险是"不报错的失败"** —— 已定位 **13 条静默失效路径**（判分器无 key 静默降级为帧差、JSON 解析失败伪装成 0 分、两套 16 维布局用错不报错、Stage 5 一键脚本 `--tags` 与产物文件名不匹配……），且至少 5 组常量被重复定义。**下任何"模型不行"的结论前，先跑 `L01` 的审计四件套。**
