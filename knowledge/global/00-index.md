# 全局知识层 · 索引

> 更新日期：2026-08-30
> **这一层是什么**：把四个已复现项目（`genie_sim_v3` / `lw_benchhub` / `genesis_world` / `ge_sim_v2`）的五层文档**横向综合**成 5 篇跨项目文档。回答的是"**任何**具身智能仿真工具链复现/使用时都会遇到什么"，而不是"某个项目怎么样"。
> **这一层不是什么**：⚠️ **它是派生层，不是新事实来源** —— 结论全部来自项目层，不新增证据。**与项目层冲突时，以被引用的那一层为准。**
> **给 Claude Code 的一句话用法**：新工具链、没有对应项目文档时，**先读这一层**；已经锁定某个项目时，**直接进项目层**，这一层只在"该怎么做事"和"这个词什么意思"两种时候回来查。

## 5. 检索协议：全局层与项目层的先后顺序

**四条规则，按优先级：**

1. **有项目文档就优先项目层。** 全局层是派生层，粒度更粗。已经知道是 `genesis_world` 的问题，就直接进 `projects/genesis_world/`，不要在全局层绕。
2. **带逐字报错原文时，先项目层 `troubleshooting.md` 的症状索引**（可直接 `Ctrl-F` 报错原文）；**查不到再回全局层 `common_issues_solutions.md` 按类别定位**。
3. **没有对应项目文档时（新工具链），全局层是唯一入口**：`common_reproduction_guide.md` 给流程，`common_issues_solutions.md` 给已知坑的形状，`best_practices.md` 给纪律。
4. **冲突时以被引用的那一层为准。** 全局层每条结论都注明了出处项目与编号，回去读原文。

**读取纪律**（与项目层一致）：

| 规则 | 说明 |
|---|---|
| 按需读取 | `common_issues_solutions.md` 有 759 行。**先用本文 §2 的行号表，再 `Read` 的 `offset`/`limit` 精准读取**，不要整篇载入 |
| 认证据等级 | 全局层不重新定级，沿用项目层标注：工程决策**只信 `[CODE]`**；`[实践]` 是本机踩坑记录、不等于官方结论；`[官网]`/`[PAPER]` 是宣称值 |
